# Mosquito Tone

A small, installable high-frequency tone generator. Tap the large button to
start; tap again to stop. The sine-wave samples are generated by a Zig
WebAssembly module inside a Web Audio AudioWorklet, not by a prerecorded file
or a JavaScript oscillator standing in for WASM.

**[Open Mosquito Tone](https://pmarreck.github.io/mosquito_tone/)** in your browser.

The default is 17.4 kHz at a low digital signal level. Frequency is adjustable
from 14 to 19 kHz. Playback continues until you tap Stop, the page is hidden,
or the audio context is interrupted. There is no time limit and it never starts automatically.
Output runs locally and can work offline once the app has cached its assets.

## Install on iPhone

Open the deployed HTTPS URL in Safari. Tap Share, Add to Home Screen, enable
Open as Web App if offered, then Add. The app's Install button repeats these
steps; a website cannot open Apple's installation sheet itself.

Open the app online once before relying on offline use. The app plays audio
locally and requires no account.

If Safari reports that a service-worker response has redirections after an
update, close and reopen the app online so the corrected worker can activate.
If an older worker remains stuck, remove only this site's entry under Safari's
Advanced > Website Data settings, then reopen it online. This resets its
offline cache.

Start with the phone's physical volume low. The signal slider controls digital
amplitude, not calibrated acoustic loudness. Not hearing a tone does not mean
it is quiet to someone else. High-frequency hearing varies, some adults can
hear these tones, and phone speakers may attenuate them or produce artifacts.
This is neither a clinical hearing test nor a child-only sound.

## Development

Nix controls the build and test dependencies. Zig is pinned to 0.16 through
the locked Nixpkgs input, matching a known working freestanding WASM pipeline.
The app has no third-party JavaScript dependencies.

```sh
./build       # canonical nix build; dist-out links to the static site
./test        # complete required tests for the current builder
./run         # local preview at http://127.0.0.1:8421/
```

The output is platform-independent static HTML/CSS/JavaScript/WASM. Declared
Nix builder systems are Linux amd64/arm64 and macOS arm64. Linux checks include
headless Chromium; other builders run the core/model/package checks. Real
Safari and iPhone Home Screen qualification remains separate from desktop
browser evidence.

Tests exercise the actual WASM against independent sine samples and frequency
energy calculations at 44.1 and 48 kHz; buffer continuity, fade-to-silence and
invalid parameters; bounded settings; PWA assets;
and real browser AudioWorklet start/stop, continuous playback, lifecycle handling, errors
and offline reload. Browser tests mute output so tests do not emit tones into
the room. They use temporary profiles and a loopback-only server.

`nix log .#checks.x86_64-linux.test` shows the detailed Linux test receipt.
Tests are fast after dependencies are available; fetching a browser is setup
cost, not test execution time.

The [Pages workflow](.github/workflows/pages.yml) builds with Nix and runs the
complete test suite before publishing a push to `yolo`. It is also available
under **Actions → Publish GitHub Pages → Run workflow**. GitHub Pages receives
only the generated site. For manual static hosting, run `./build`, `./test`,
and `./stage-release`, then upload the contents of `dist/`.

## Implementation

`src/tone.zig` owns oscillator phase, the 20 ms amplitude ramp, validation and
a fixed sample buffer. `web/tone-worklet.mjs` instantiates that WASM and copies
its samples into the audio output. `web/app.mjs` owns explicit user activation,
gain, UI, cancellation and lifecycle. Settings validation is pure in
`web/model.mjs`. The offline cache is versioned by asset and worker content.
Cached app navigations reconstruct a response without fetch redirect metadata,
which Safari rejects for navigation. Host authentication routes bypass the
offline app handler. A regression test checks this response contract; Chromium
tests additionally verify real offline reloads. This does not substitute for
native Safari qualification.
